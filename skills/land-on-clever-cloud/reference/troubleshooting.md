# Troubleshooting — the message you see is a symptom, the cause is above it

Read the failing deployment from the TOP: `clever activity` for the id, then
`clever logs --deployment-id <id> --until now | bash <skill>/scripts/mask.sh` (or `--since 20m --until
now`; the app's logs can print its own variables: always through `mask.sh`). Match the
**first** abnormal line, not the last one. Two fix attempts, then stop and report what you
observed, the cause you believe, and the next thing to try. Never loop on redeploys.

| First abnormal line | Cause | Fix |
|---|---|---|
| `Killed` during build, then "not listening on 8080" | out of memory on the build VM | `clever scale --build-flavor L`; keep the instance small |
| `Killed` at run time, no trace | out of memory on the instance | bigger `--flavor`, or reduce workers (gunicorn, Node cluster) |
| Next.js: `Killed`, 502/503, `Monitoring/Unreachable`, back about 3 min later, under image traffic | nano cannot hold `/_next/image` optimisation (test T6, 2026-10-26: 50 requests at 4 in parallel) | XS at least (`clever scale --flavor XS`); the plan already sizes it XS |
| "listening on localhost instead of publicly" | bind `127.0.0.1` | bind `0.0.0.0` (`HOST=0.0.0.0`, `--host 0.0.0.0`, `next start -H 0.0.0.0`) |

| `migrate-sqlite.py` says `REFUSED <table>.<column>: N value(s) are numbers, not dates` (a column bound for a timestamp, timestamptz, date or time column holds integers or reals) | the unit of a number is unknown — a Unix epoch in seconds or milliseconds (Prisma's SQLite storage [assumed]: check one row), a Julian day, YYYYMMDD — and PostgreSQL would read some of them as dates without a word (the Julian day 2460311 became 0246-03-11): the script never reads a number as a date, never rewrites one; nothing was copied. A column whose values fall on both sides of 1e11 cannot be decided by one rule (a millisecond epoch before 1973 is below it, a 1971 birth date read as seconds becomes the year 3322): do not convert it with one statement — look at its rows. No ready-made rewrite here: a statement run on the `.db` copy is invisible to the copy's own checks |
